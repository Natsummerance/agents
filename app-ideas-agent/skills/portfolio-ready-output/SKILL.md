# SKILL.md - Portfolio-Ready Output（作品集就绪输出）

## R (Reading) - 原文引用

> "These applications are:"
> "- great for adding to your portfolio to impress your next employer/client :file_folder:;"

## I (Interpretation) - 方法论骨架

**核心思想**：项目完成后可以直接添加到作品集中，用于吸引雇主或客户。这种"作品集就绪"的设计思维确保学习者的努力能够转化为实际的职业价值，而不仅仅是练习。

**关键要素**：
1. **视觉吸引力**: 项目应该有清晰的 UI/UX，能够直观展示技能
2. **功能完整性**: 项目应该实现核心功能，而不是半成品
3. **技术栈多样性**: 使用不同的技术栈展示广泛的能力
4. **可访问性**: 项目应该可以在线演示或提供清晰的截图

## A1 (Past Application) - 书中作者用过的案例

App Ideas Collection 明确将"添加到作品集以吸引雇主/客户"列为核心 benefits 之一。89 个项目都设计为：
- 易于完成且可扩展
- 有清晰的目标描述
- 适合用作教程示例

这种设计使得每个项目都可以直接作为作品集项目，而不需要额外的包装或修饰。

## A2 (Future Trigger) - 用户在什么情境下会需要这个

**适用场景**：
- 用户正在准备求职，需要构建有吸引力的作品集
- 用户想评估某个项目是否值得投入时间
- 用户想知道如何让项目更有职业价值
- 用户完成了几个项目，但不知道哪些适合放入作品集

**与相邻 skill 的区分**：
- 与 `tiered-learning-path` 的区别：portfolio-ready-output 关注**项目的职业价值**，而 tiered-learning-path 关注**学习路径的选择**。两者可以组合使用：先根据难度选择项目，再确保该项目适合放入作品集。

## E (Execution) - 可执行步骤

1. **评估项目的作品集价值**
   - 检查项目是否有清晰的 UI/UX
   - 确认项目实现了核心功能
   - 评估技术栈是否具有市场价值

2. **优化项目展示**
   - 添加 README.md，说明项目目标、技术栈和实现细节
   - 提供在线演示链接或清晰的截图
   - 突出项目的独特之处和技术难点

3. **构建多样化作品集**
   - 包含不同技术栈的项目（前端、后端、全栈）
   - 包含不同难度的项目（展示成长轨迹）
   - 确保每个项目都有明确的业务价值

4. **定期更新作品集**
   - 移除过时或简单的项目
   - 添加新的、更有挑战性的项目
   - 保持作品集的最新状态

## B (Boundary) - 什么时候不适用

**不适用场景**：
- 纯学习练习（不打算展示给他人）
- 内部工具开发（不需要外部可见性）
- 快速原型验证（不需要完整实现）
- 个人兴趣项目（不以求职为目的）

**作者的盲点**：
- app-ideas 假设所有学习者都以求职为目标，但实际上有些人可能只是为了兴趣或自我提升
- 缺少关于如何具体优化项目展示的指导（如 README 结构、截图技巧等）
- 没有提到如何将多个项目组织成连贯的作品集叙事
