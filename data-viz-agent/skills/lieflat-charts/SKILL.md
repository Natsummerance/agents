# Lieflat Charts · 扁平化商业图表风格系统

## R (Reading) — 上游原文

> 「它以统一的字体、留白、线条和动效建立自己的视觉语法……Lupi（编辑叙事型）：用细线、点阵、逐条记录和大量留白展开数据，强调真实单位、细节和旁注；Glance（快速判断型）：用粗柱、大数字、色块和清晰排序提前聚合信息，让读者几秒内看懂高低、变化和异常；Basics（基础编辑型）：保留柱状图、折线图等熟悉轮廓，再用可数刻度、发丝线和编辑排版增加质感。」
>
> — 上游 README.md（larashero3-dotcom__lieflat-charts）

上游 SKILL.md 把选型写成硬约束：「默认选型顺序固定。先完整比较 Lupi Editorial（L1–L20），再比较 Lupi Basics（F1–F17）……只有 Lupi 与 Basics 候选全部失败，或用户明确要求 Glance、dashboard、监控、周报、三秒快读时，才使用 Glance。」并规定「同一份 HTML 或同一组交付只能锁定一种色彩系统，不得混用」。

关于图数的契约，README.md 写道：「图数由独立结论决定：单个问题通常 1 张，两个到三个结论 2–3 张，完整文章或论文 4–6 张，单页默认最多 6 张。用户明确指定数量时会遵守，但不会为了凑数重复表达同一个结论。」

## I (Interpretation) — 方法论骨架

1. **数据形状是选图的主键**：先看数据长什么样——少类目比较、时间序列、占比构成、带正负、分布、多对一归属、网络——不问用户想要什么图。形状决定候选池；场合决定阅读速度：年报/论文/海报走 Lupi 细读（30s+），周报/dashboard 走 Glance 扫一眼（<10s）。
2. **选型顺序是硬约束不是偏好**：主力 Lupi Editorial L1–L15 与 Lupi Basics F1–F13 先行，每张图至少比较 3 个候选并写明淘汰理由；后备 L16–L20/F14–F17 仅在主力不适配时启用，且五种形状可直接取后备（OHLC→F17 K线、五数概括→F15 Tick Box、3–6 连续维度→L20 平行坐标、52×7 全年日历→L17 Calendar Heat、总量+构成的连续流→F16 Stream Ribbon）；Glance 是降级方案，启用必须写明 Lupi/Basics 为何不行。
3. **一张图只承担一个独立结论**：图数由结论数决定而非字段数——单问题 1 张、2–3 结论 2–3 张、整篇文章 4–6 张、单页上限 6 张；一页多图时模板不重复、形状轮换、暗卡每屏最多 1 张。
4. **诚实编码红线**：柱状图不断轴（极端值用冲天/放大镜小图/撕柱不撕轴三替代）；数值与视觉严格成正比（面积编码用 sqrt 换算半径）；演示数据用确定性 rnd(i,k)，禁用 Math.random()；一律实心不发光不渐变不阴影；SVG 最小字号半宽卡 6.5px、通栏 5.5px。
5. **卡片四件套与结论式标题**：结论式标题（写判断不写图型名，如 "Where we gained, where we bled"）+ 副标题（说明·图例·时间范围）+ 图 + 全大写来源行；字体 Inter 全家，标题 700/数值 800/轴标签 600。
6. **色彩系统单一锁定**：Mono 纸灰 #F0EFEB × 炭黑 #1C1C1A 加 7 级灰阶 ladder 是保底，明度即数据；porcelain 单色相蓝阶配有序单序列、palm 低饱和绿黄配 ≤4 个无序类目、wire 灰阶加一个荧光橙落点；同一份交付只锁一套系统，custom 色板仅在用户给出品牌色时按角色（BG/TXT/MUT/GRID/DATA/HERO/RAMP/CAT）建立，正文对比度 ≥4.5:1。
7. **交互三问与库外翻译流程**：元素背后无真实记录禁止加 hover；<50 个且两端有标注静态够用；>50 根或多段路径必须可查。库外图型先答本体（每个视觉通道编码哪个维度）→ 找 catalog 最近亲戚继承骨架 → 用 mono-tokens.js 造句 → 过同一套自检；抄形不抄魂等于白做。
8. **输出模式判定前置**：默认图表模式；只有用户明确说出「报告/年报/月报/白皮书/一页纸/海报/brief/dashboard 报告」才进报告模式（读 report-catalog.md 选 R01–R12 整页骨架，页内图表仍按 catalog 选型）；歧义时先交最强单图并提示可切换。

## A1 (Past Application) — 源项目典型应用

### 案例: 周报数据的快速判读图
- **输入**: 一份含排名与环比变化的销售周报 CSV，用户要求「10 秒内看懂排名、变化和异常」
- **做法**: 用户显式要求快读，跳过证伪直接进 Glance 池；Chunky Bars 承载排序、Diverging Bar 承载正负变化，粗线大数、结论写进标题
- **结果**: 单文件 HTML 图表页，扫一眼即得高低、方向与异常，符合 dashboard 阅读速度

### 案例: 论文结论的一页完整图表
- **输入**: 一篇论文全文，要求「找出最值得讲的几个数据结论，做成一页完整的 HTML 图表」
- **做法**: 先提炼独立结论数 → 按图数规则出 4–6 张覆盖总览/构成/比较/关系不同形状 → 全局分配确保模板不重复、形状轮换、至多一张暗卡
- **结果**: 有整页叙事的单文件 HTML，每张图可回溯到 catalog 编号、gallery 文件与卡内标题

### 案例: 公众号调研数据的单位分解
- **输入**: 一篇调研文章的百分比数据（占比加总 100%），场合是公众号长文细读
- **做法**: 默认先比 Lupi Editorial 与 Basics 候选；用单位分解把聚合数摊回可数单位（1 点 = 1 人），取整加总不足 100 时底注注明被四舍五入吃掉的人数，不编造假单位
- **结果**: 密度来自单位而非记录数的编辑感图表，读者愿意停留细看且每个点有真实含义

## A2 (Future Trigger) ★ 触发场景

### 用户会在什么情境下需要
1. 手上有数据只说「可视化/分析一下/做几张图」，没指定工具或格式——默认产出扁平风单文件 HTML 图表而非报告
2. 周报、汇报、监控、dashboard 场景，要求几秒内看懂排序、变化和异常（Glance 显式触发）
3. 年报、公众号长文、海报、作品集等愿让人细读的场合，或点名「报告/年报/白皮书/一页纸」（报告模式触发）

### 语言信号
- "把这季度转化画一下，发公众号用"
- "这是一份周报数据，要求 10 秒内看懂排名、变化和异常"
- "用 Lupi 风格重新设计这组数据，保留每条真实记录，并加入必要的旁注"
- "读这篇论文，找出最值得讲的几个数据结论，做成一页完整的 HTML 图表"
- "用青瓷蓝预设重做这张图"、"做个年报/白皮书的一页纸"

- "把这份周度指标做成 dashboard 一页，谁高谁低一眼看出来"
- "给这批数据配一套黑白杂志感的图，重点只标一个数"

### 与同 agent 兄弟 skill 的区分
- 与 `scientific-figures` 的区别一句话：本 skill 产出**浏览器阅读的扁平化商业 HTML 图表/报告**（编辑设计感、动效、公众号/汇报/年报场合），scientific-figures 产出 **matplotlib 出版级静态学术插图**（PDF/SVG 矢量导出进论文排版）。

## E (Execution) — 可执行步骤

1. **判定输出模式** — 完成标准: 明确宣布进入图表模式或报告模式；仅当报告关键词齐全才开报告模式，歧义时选图表模式并向用户提示可切换
2. **判数据形状并审计候选** — 完成标准: 用一句话写出数据形状；列出至少 3 个候选（体系+编号+淘汰理由），顺序为先 Lupi Editorial 再 Lupi Basics；启用 Glance 或后备时附书面不适配说明
3. **锁定真实模板** — 完成标准: 每张图记录图型编号、gallery 文件与卡内标题，成品核心结构确实来自该卡的 `<div class="card">` 与同名注释块，未拼接、未另画近似图
4. **确定图数与全局分配** — 完成标准: 每张图对应一个独立结论，重复结论已删；单页 ≤6 张、无相似轮廓堆叠、暗卡每屏 ≤1 张
5. **渲染替换与色彩锁定** — 完成标准: 只替换数据/标题/旁注/来源，核心几何、比例与动画节奏不变；整份交付锁定 Mono 或单一预设/custom 之一并通过对比度检查
6. **交付前自检** — 完成标准: 自检清单逐项通过——面积 sqrt 换算、柱未断轴、最小字号达标、rnd 刷新两次一致、reveal 与 reduced-motion 正常、脚本语法检查通过、标题为结论而非图型名、成品放回 gallery 卡旁仍是同一家族

## B (Boundary) — 边界

### 不适用场景
- 学术论文投稿用的 matplotlib 出版插图、矢量 PDF/SVG/eps 导出、LaTeX 数学标注 → 转 `scientific-figures`
- 搭建持续运行的 BI 工程（Tableau/PowerBI/自建看板服务）或统计建模分析本身——本 skill 只负责把数据画对画好
- 用户要 PowerPoint 原生可编辑图表对象（.pptx 内嵌 chart）的场合
- 纯装饰信息图/插画（无真实数据契约可审计）——本 skill 每张图都必须通过数据契约检查

### 已知局限 / 失败模式
- Glance、Interactive 大图及报告模板 R11/R12 经 CDN 加载 Chart.js/ECharts，断网无法完整显示（纯 SVG 的 Lupi/Basics 可离线）
- 地图仅支持 M1 美国州级 / M2 世界国家级 choropleth 且只在用户明确要求时启用；中国地图不套用改名，须另行满足合规审图要求
- 上游采用 PolyForm Noncommercial License 1.0.0，商业使用需另行取得许可
- 单文件 HTML 内联 token 与依赖后体积随图数增长，超长报告页在低配移动端浏览器可能加载缓慢
