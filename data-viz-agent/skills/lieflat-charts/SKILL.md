# Lieflat Charts · 扁平化商业图表风格引擎

## R (Reading) — 上游原文

> 「它以统一的字体、留白、线条和动效建立自己的视觉语法……Lupi（编辑叙事型）：用细线、点阵、逐条记录和大量留白展开数据，强调真实单位、细节和旁注；Glance（快速判断型）：用粗柱、大数字、色块和清晰排序提前聚合信息，让读者几秒内看懂高低、变化和异常；Basics（基础编辑型）：保留柱状图、折线图等熟悉轮廓，再用可数刻度、发丝线和编辑排版增加质感。」
>
> — 上游 README.md（larashero3-dotcom/lieflat-charts）

上游 SKILL.md 进一步把选型写成硬约束：「默认选型顺序固定。先完整比较 Lupi Editorial（L1–L20），再比较 Lupi Basics（F1–F17）……只有 Lupi 与 Basics 候选全部失败，或用户明确要求 Glance、dashboard、监控、周报、三秒快读时，才使用 Glance。」

## I (Interpretation) — 方法论骨架

1. **数据形状是选图的主键**：先看数据长什么样（比较/序列/占比/分布/归属/网络），不问用户想要什么图。形状决定候选池，场合决定阅读速度（Lupi 细读 30s+ vs Glance 扫一眼 <10s）。
2. **选型顺序是硬约束不是偏好**：主力 Lupi Editorial L1–L15 与 Lupi Basics F1–F13 先行，每张图至少比较 3 个候选并写下淘汰理由；后备 L16–L20/F14–F17 只有主力不适配时可用（OHLC 行情、五数概括、平行坐标、全年日历热力、流带五种形状可直接取后备）；Glance 是降级方案，启用必须写明 Lupi/Basics 为何不行。
3. **一张图只承担一个独立结论**：图数由独立结论数决定（单问题 1 张、2–3 结论 2–3 张、整篇文章 4–6 张、单页上限 6 张），不为凑数重复表达；一页多图时模板不重复、形状轮换、暗卡每屏最多 1 张。
4. **诚实编码红线**：柱状图不断轴；数值与视觉严格成正比（面积用 sqrt 换算半径）；演示数据用确定性 rnd 不用 Math.random()；一律实心、不发光不渐变不阴影；最小字号半宽卡 6.5px / 通栏 5.5px。
5. **卡片四件套与结论式标题**：结论式标题（写判断不写图型名）+ 副标题（图例·单位·时间范围）+ 图 + 全大写来源行；标题写 "Where we gained, where we bled"，不写「柱状图」。
6. **色彩系统单一锁定**：Mono 黑白灰是保底，porcelain（有序单序列明度阶）/ palm（少量无序类目）/ wire（灰阶+一个荧光橙落点）按数据语义自动选择；同一份 HTML 或同一组交付只能锁定一种系统，custom 色板仅在用户给出品牌色时启用，正文对比度 ≥4.5:1。
7. **库外图型走翻译流程**：先回答本体（每个视觉通道编码什么维度）→ 找 catalog 最近亲戚继承骨架 → 用 mono-tokens.js 造句 → 过同一套自检；抄形不抄魂等于白做。
8. **输出模式判定前置**：默认图表模式；只有用户明确说出报告/年报/月报/白皮书/海报/brief/dashboard 报告等关键词才进报告模式（R01–R12 整页模板），歧义时先交付最强单图并提示可切换。

## A1 (Past Application) — 源项目典型应用

### 案例: 周报数据快速判读
- **输入**: 一份含排名、环比变化的销售周报 CSV，用户要求「10 秒内看懂排名、变化和异常」
- **做法**: 用户显式要求快读 → 直接进入 Glance 候选池；Chunky Bars 承载排序、Diverging Bar 承载正负变化，粗线大数结论进标题
- **结果**: 单文件 HTML 图表页，几秒内读出高低与异常，符合周报/dashboard 场合

### 案例: 论文数据结论的一页图表
- **输入**: 一篇论文全文，要求「找出最值得讲的几个数据结论，做成一页完整的 HTML 图表」
- **做法**: 先提炼独立结论数 → 按图数规则出 4–6 张覆盖不同数据形状的图 → 全局分配模板不重复、形状轮换
- **结果**: 单页多图的完整叙事，每张图可追溯到 catalog 编号与 gallery 卡片

### 案例: 公众号长文的调研数据
- **输入**: 一篇调研文章的核心百分比数据（占比加总 100%），要求适合公众号长文细读
- **做法**: 默认先比 Lupi Editorial 与 Lupi Basics；采用单位分解——1 点 = 1 人摊开成 Hundred Field/Dot Waffle，取整不足 100 时底注说明被四舍五入吃掉的人数，不凑假单位
- **结果**: 有密度、有可数单位、有旁注的编辑感图表，读者愿意停下来细看

## A2 (Future Trigger) ★ 触发场景

### 用户会在什么情境下需要
1. 手上有数据只说「可视化/分析一下/做几张图」，没指定工具——默认输出扁平风 HTML 图表而非报告
2. 周报、汇报、监控、dashboard 场景要求几秒内看懂排序与异常（Glance 触发词）
3. 年报、公众号长文、海报、作品集等愿意让人细读的场合，或明确点名「报告/年报/白皮书/一页纸」（报告模式触发词）

### 语言信号
- "把这季度转化画一下，发公众号用"
- "这是一份周报数据，要求 10 秒内看懂排名、变化和异常"
- "用 Lupi 风格重新设计这组数据，保留每条真实记录，并加入必要的旁注"
- "读这篇论文，做成一页完整的 HTML 图表"
- "用青瓷蓝/椰林绿/编辑部红重做这张图"、"做个年报/白皮书的一页纸"

### 与同 agent 兄弟 skill 的区分
- 与 `scientific-figures` 的区别：本 skill 产出**浏览器阅读的扁平化商业 HTML 图表/报告**（编辑设计感、交互动效、公众号/汇报场合）；scientific-figures 产出 **matplotlib 出版级静态学术插图**（PDF/SVG 矢量导出进论文）。用户提论文、期刊、投稿 → 转 scientific-figures。

## E (Execution) — 可执行步骤

1. **判定输出模式** — 完成标准: 明确宣布进入图表模式或报告模式；只有报告关键词齐全才进报告模式，歧义时选图表模式并向用户提示可切换
2. **判数据形状并审计候选** — 完成标准: 用一句话写出数据形状，列出至少 3 个候选（体系+编号+淘汰理由），顺序为先 Lupi Editorial 再 Lupi Basics，Glance 启用时附不适配说明
3. **锁定真实模板** — 完成标准: 每张图记录图型编号、gallery 文件与卡内标题，成品核心结构确实来自该卡的 `<div class="card">` 与同名注释块
4. **确定图数与全局分配** — 完成标准: 每张图对应一个独立结论，重复结论已删除，单页不超过 6 张且无相似轮廓堆叠、暗卡不超标
5. **渲染替换** — 完成标准: 只替换数据/标题/旁注/来源，保留所选模板的核心几何、编码方式与动画节奏；整份交付锁定单一色彩系统
6. **交付前自检** — 完成标准: 自检清单逐项通过——比例正比、未断轴、最小字号达标、rnd 确定性、reveal 与 reduced-motion 正常、脚本语法检查通过、标题是结论而非图型名

## B (Boundary) — 边界

### 不适用场景
- 学术论文投稿用的 matplotlib 出版插图、矢量 PDF/SVG 导出 → `scientific-figures`
- 搭建持续运行的 BI 系统/Tableau/PowerBI 工程，或统计建模分析本身（本 skill 只管把数据画对画好）
- 用户明确要 PowerPoint 原生可编辑图表对象（.pptx 内嵌 chart）的场合
- 纯装饰性的信息图/插画需求（无真实数据契约可审计）——本 skill 每张图都要通过数据契约检查

### 已知局限 / 失败模式
- Glance、Interactive 及报告模板 R11/R12 经 CDN 加载 Chart.js/ECharts，断网时无法完整显示（纯 SVG 的 Lupi/Basics 可离线）
- 地图仅支持 M1 美国州级 / M2 世界国家级 choropleth，且只在用户明确要求时启用；中国地图不套用改名，须另行满足合规审图
