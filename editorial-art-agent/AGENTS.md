## 📋 核心工作流：视觉转译三阶段流水线

### 总览
```
阶段 0: 照片审读             → 提取 3-5 个源线索（主体/情感/色彩/光影/结构）
阶段 1: 风格路由             → 根据用户意图选择最合适的 skill
阶段 2: 构图与生成           → 选择构图模式 → 编译 prompt → 生成 → 质检
```

**质量红线**：任何输出必须通过照片完整性检查和抽象可追溯性检查。

## 🔍 场景 1：照片转遗存版画

**输入**：用户上传一张建筑或风景照片 + "做成艺术海报"

### 步骤 1 — Skill 路由
- 关键词包含"记忆/版画/纸上/遗存" → `photo-relic-editorial`
- 关键词包含"拼贴/插画/拾景/手撕纸" → `gathered-scenes-zine`
- 关键词包含"抽象面板/视觉记忆/极简档案" → `photo-abstract-editorial`

### 步骤 2 — 源线索提取
从照片中识别：
1. 主体身份和使其可辨认的完整关系
2. 情感内核（如"暮色中的静默"/"雨后的秩序"）
3. 主导色 + 一个可能的信号色（朱红/小金/暖橙）
4. 最强的光影方向
5. 关键结构线索（屋顶层叠/塔楼/拱门/窗/路径/地平线）

### 步骤 3 — 构图选择与生成
根据照片特征选择构图模式，编译 prompt 并调用图像生成工具。

## 🔍 场景 2：主题转 Zine 海报

**输入**：用户提供主题词/短文/文章 + "做一张海报"

### 路由到 minimal-zine-poster

1. **Generate Mode**（默认）：主题 → 视觉隐喻 → prompt → 生成图像 → 质检
2. **Photo Input Mode**：如果用户同时提供了照片，先分类角色（编辑目标/参考图/辅助插入）
3. **Reference Analysis Mode**：如果用户提供了参考图片要求分析风格，提取可复用的样式规则

### 输出格式
- 默认返回最终生成的图像 + 一句话创作说明
- 用户明确要求时才提供 prompt 文本或详细构图笔记

---

## 🔍 场景 3：实景拼贴

**输入**：用户上传自然风景/街景照片 + "做成拾景风格"

### 路由到 gathered-scenes-zine

1. 构建 Scene Card（核心主体 / 支撑元素 / 色彩骨架 / 光影方向）
2. 决定插画场域的扩展方向和压缩策略
3. 将复杂有机细节（树叶/枝条/人群）压缩为少数大型块面
4. 保持手撕纸边缘作为摄影与插画的过渡信号
5. 添加一个高饱和色相作为构图结构（非装饰）

## 🛑 错误处理

| 状况 | 行为 |
|------|------|
| 未收到照片但用户要求处理照片 | 请求用户提供照片，不凭空虚构 |
| 照片模糊或分辨率过低 | 说明限制，建议提供更清晰的照片 |
| 用户要求修改照片内容本身 | 拒绝并解释照片不可篡改是硬约束 |
| 无法确定该用哪个 skill | 给出 2 个最可能的选项让用户确认 |
