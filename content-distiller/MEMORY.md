- **原因**: 将内容蒸馏能力集成到 OpenClaw 生态，使其可作为独立 agent 使用
- **结果**: 成功创建 29+ 个文件，包含完整的 RIA-TV++ 流水线

### 核心执行原则

1. **必须提供源文本**
   - 没有文本就不能开始蒸馏
   - 视频/播客需要先用 video-downloader 提取转写文本
   - 不要凭记忆或网络搜索来蒸馏

2. **用户确认是关键节点**
   - 阶段 0 后：确认骨架理解
   - 阶段 1.5 后：确认入选名单
   - 阶段 5 前：确认安装位置
   - 跳过确认会导致大量返工

3. **三重验证不能降低标准**
   - V1 跨域：至少 2 处独立佐证
   - V2 预测力：能回答新问题
   - V3 独特性：超越常识
   - 通过率通常只有 25-50%，这是正常的

4. **保留审计轨迹**
   - candidates/ 保留所有候选
   - rejected/ 保留淘汰记录及原因
   - PIPELINE_STATE.md 记录进度
   - 允许事后捞回被淘汰的候选

5. **压力测试必须严格**
   - 每个 skill 必须有 test-prompts.json
   - 包含应调用 / 不应调用（诱饵）/ 边界模糊三类测试
   - 诱饵中至少 1 条是跨 skill 混淆测试
   - 测试通过率 <80% 必须回炉重做

## 🔧 常见错误模式

### 错误模式 1: 没有源文本就开始
**修复**: 停下来问用户提供文本文件路径

### 错误模式 2: 跳过用户确认
**修复**: 在阶段 0、1.5、5 必须请求用户确认

### 错误模式 3: 并行提取变成串行
**修复**: 使用 sessions_spawn 同时启动 5 个 sub-agents

### 错误模式 4: 三重验证不严格
**修复**: 严格执行 V1/V2/V3 三项检验

### 错误模式 5: SKILL.md 缺少关键字段
**修复**: 严格按照模板填充 R/I/A1/A2/E/B 六段

### 错误模式 6: 没有安装 skills
**修复**: 阶段 5 必须询问安装位置并实际安装
