# Content Distiller 使用示例

## 示例 1: 蒸馏《穷查理宝典》

### 用户请求
```
用户: 帮我拆《穷查理宝典》
```

### Agent 响应流程

#### 步骤 1: 确认输入
```
Agent: 好的，我来帮你蒸馏《穷查理宝典》。

首先，请提供《穷查理宝典》的文本文件路径。
支持格式：PDF / EPUB / TXT

例如：/path/to/poor-charlies-almanack.txt
```

#### 步骤 2: 用户提供文本
```
用户: /home/user/books/poor-charlies-almanack.txt
```

#### 步骤 3: 阶段 0 - Adler 整书理解
```
Agent: 正在读取文本并执行 Adler 四步分析...

[读取文本，分块处理]

已完成 BOOK_OVERVIEW.md，包含：
- 主旨总结：多元思维模型、逆向思维、能力圈等核心概念
- 骨架结构：演讲集形式，涵盖投资、商业、人生智慧
- 关键术语：能力圈、护城河、安全边际、lollapalooza 效应
- 批判性思考：时代局限性、美国中心视角

请确认：骨架我理解对了吗？有没有你希望重点突出的方向？
```

#### 步骤 4: 用户确认
```
用户: 理解正确，重点突出投资决策框架和思维模型
```

#### 步骤 5: 阶段 1 - 并行提取
```
Agent: 正在启动 5 个 sub-agents 并行提取...

✓ framework-extractor: 提取到 18 个思维模型
✓ principle-extractor: 提取到 25 个原则
✓ case-extractor: 提取到 12 个案例
✓ counter-example-extractor: 提取到 8 个反例
✓ glossary-extractor: 提取到 30 个术语

候选池已保存到 books/poor-charlies-almanack/candidates/
```

#### 步骤 6: 阶段 1.5 - 三重验证筛选
```
Agent: 正在执行三重验证...

验证结果：
- 通过: 15 个候选（通过率 32%）
- 淘汰: 32 个候选

通过的候选列表：
1. 逆向思维 (framework)
2. 能力圈原则 (principle)
3. 多元思维模型 (framework)
4. 安全边际 (principle)
5. lollapalooza 效应 (framework)
...

请确认：这 15 个会做成 skill，有想捞回或砍掉的吗？
```

#### 步骤 7: 用户确认
```
用户: 没问题，开始生成 skills
```

#### 步骤 8: 阶段 2-4 - 构造 + 链接 + 测试
```
Agent: 正在构造 skills...

进度汇报：
- 已完成 5/15 skills
- 已完成 10/15 skills
- 已完成 15/15 skills

压力测试结果：
- 平均通过率: 87%
- 所有 skills 通过阈值
```

#### 步骤 9: 阶段 5 - 交付
```
Agent: 已完成！

输出目录: books/poor-charlies-almanack/

请问你想把 skills 安装到哪里？
1. 用户级: ~/.openclaw/skills/poor-charlies-almanack/
2. 项目级: .openclaw/skills/poor-charlies-almanack/
```

#### 步骤 10: 用户选择
```
用户: 安装到用户级
```

#### 步骤 11: 完成
```
Agent: 已完成！

15 个 skills 已安装到 ~/.openclaw/skills/poor-charlies-almanack/

你现在可以在对话中自然提及触发场景，skills 会自动激活。
```

## 示例 2: 蒸馏 B 站长视频

### 用户请求
```
用户: 把这个 B 站视频蒸馏成 skill: https://www.bilibili.com/video/BV1xx
```

### Agent 响应
```
Agent: 好的，我来帮你蒸馏这个 B 站视频。

首先，请用 video-downloader 下载视频并提取字幕/转写文本：

video-downloader --url https://www.bilibili.com/video/BV1xx --output transcript.txt

或者如果你已经有转写文本，直接提供文件路径即可。
```

### 用户提供转写文本
```
用户: /home/user/videos/transcript.txt
```

### 后续流程同上
```
Agent: 收到转写文本。

元信息确认：
- 标题: [从文件名或用户处获取]
- 作者: [UP 主名称]
- 发布时间: [发布日期]

请确认这些信息是否正确？
```

## 示例 5: 使用生成的 skills

### 场景 1: 投资决策
```
用户: 我在纠结一个投资决策，列举了正面理由但理不出头绪

Agent: [自动激活"逆向思维" skill]

根据《书名》的"逆向思维"框架，让我们换个角度思考：

1. 不直接问"怎么达成"，而先问"什么会让我失败"
2. 列出失败因素
3. 避免这些因素，反向推出应做的事
```

```
用户: 这个商业模式看起来不错，但我看不懂它的盈利逻辑

Agent: [自动激活"能力圈原则" skill]

建议：
1. 承认自己不懂，不要强行投资
2. 如果真想投资，先深入学习该行业的知识
3. 或者寻找你能理解的替代投资机会
```

## 常见问题

### Q1: 为什么有些候选被淘汰了？
A: 三重验证很严格，通常只有 25-50% 的候选能通过。淘汰的原因可能是：
- V1 跨域：书中只提到一次，没有独立佐证
- V2 预测力：无法用它回答新问题
- V3 独特性：是常识，没有独特洞察

### Q2: 可以调整三重验证的标准吗？
A: 不建议降低标准，但可以在阶段 1.5 确认后，从 rejected/ 中捞回某些候选。

### Q3: 生成的 skills 质量如何保证？
A: 通过以下机制保证：
- 三重验证筛选
- 压力测试（含诱饵题）
- 用户确认环节
- 审计轨迹保留

### Q4: 可以蒸馏非中文内容吗？
A: 可以，但需要注意原文引用 ≤100 词/段（英文）。

### Q5: 生成的 skills 可以分享吗？
A: 可以，但要注意遵守 AGPL-3.0 许可证，注明原始内容来源。

## 最佳实践

1. **选择方法论密集的内容**：优先选择有大量框架、原则、案例的内容

2. **提供完整的文本源**：不要只提供片段或摘要

3. **积极参与确认环节**：阶段 0 和阶段 1.5 的确认能避免大量返工

4. **先试点再批量**：第一次使用时，先蒸馏 1 份内容验证流程

5. **实际测试生成的 skills**：在真实场景中测试，记录问题和改进建议

6. **定期回顾和迭代**：根据使用反馈优化 skills
