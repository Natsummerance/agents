# AI 短视频全自动生产管线

## R (Reading) — 源项目核心设计

> "The user only needs to provide a video topic or script. Complete installation, configuration reuse, generation, waiting, and final MP4 delivery automatically."
>
> — 上游 docs/skill/SKILL.md（harry0703/MoneyPrinterTurbo）

上游把「主题进、成片出」定为唯一交付标准，并为 Agent 运行立下纪律：缺失凭据合并为一次请求且全程不回显密钥；exit code 10=索凭据 / 0=交付 / 1=按日志修复后重试一次；禁止 sleep/ps/repeat-ls 轮询；只有 `MPT_RESULT` 且文件实际存在非空才算成功。

## I (Interpretation) — 方法论骨架

1. **端到端交付观**：合法输入只有三种——主题、关键词、现成脚本；合法输出只有一个——非空 MP4 绝对路径。中间产物（脚本文本、素材链接）可以展示，但不构成完成。
2. **五段可替换流水线**：脚本（LLM 同时产出文案与素材关键词）→ 素材（Pexels/Pixabay/Coverr 免费图库、本地上传、WaveSpeed AI 文生视频三选一）→ 配音（Edge/Azure/SiliconFlow/Gemini/MiMo/ElevenLabs/Chatterbox/Fish Audio 八家 TTS）→ 字幕（edge 时间戳或 faster-whisper 转写双模式）→ ffmpeg 合成。默认组合零成本：Edge TTS + edge 字幕 + 免费图库。
3. **画幅先定，批量择优**：9:16 `1080x1920` 或 16:9 `1920x1080` 必须在生成前锁定；同参数批量产出多条候选再挑最优是上游推荐的质量策略；片段时长参数控制画面切换节奏。
4. **环境问题不伪装成业务失败**：凭据缺失走 exit 10 一次性索取；可修复错误读日志尾部修复重试一次，仍失败才上报阶段与日志路径；ffmpeg 自动下载失败属环境项，设 `IMAGEIO_FFMPEG_EXE` 或 config 中 `ffmpeg_path` 解决，而非反复重跑生成。

## A1 (Past Application) — 源项目典型应用

### 案例: 多语言科普成片
- **输入**: 中文主题「人工智能如何改变日常生活」，同时要英文版投放海外
- **做法**: LLM 分别产出中英双语脚本与各自的素材关键词，共用图库素材池，配音各选对应语言音色
- **结果**: 中英两条竖屏成片，文案独立、素材复用，兑现上游「多语言视频脚本」能力

### 案例: 专业术语的高精度字幕
- **输入**: 含大量医学术语的口播脚本，背景音乐较响
- **做法**: 字幕从默认 edge 模式切换 whisper 模式（faster-whisper 本地转写），选约 1.6GB 的 `large-v3-turbo` 平衡精度与下载成本
- **结果**: 时间轴与术语更准的字幕；首次运行需下载模型一事已提前向用户说明

### 案例: 抽象主题的文生视频兜底
- **输入**: 哲学抽象主题，图库语义检索连续错配
- **做法**: 按「图库 → 本地 → WaveSpeed 文生视频（默认 Seedance）」顺序降级，最终按关键词生成全新画面，并向用户说明该环节的费用差异
- **结果**: 画面与主题语义贴合，是否承担生成成本的决策权留给用户

## A2 (Future Trigger) ★ 触发场景

### 用户会在什么情境下需要
1. 只有一个主题或想法，希望直接拿到能发布的带配音、字幕、音乐的成片
2. 已写好文案/脚本，需要自动化装配画面、配音、字幕并导出 MP4
3. 要为多平台批量产出不同画幅版本（竖屏短视频位 + 横屏中长视频位）并择优发布

### 语言信号

- "帮我用 AI 做一条能发抖音的视频"
- "这个主题出个片子，竖屏 9:16 的"
- "文案在这里，配画面配音加字幕合成一下"
- "同一内容我要竖屏和横屏两个版本，各来几条我挑挑"

### 与相邻 skill 的区分

- 与 `gpt-image-prompting` 的区别: 本 skill 的交付物是**动态成片 MP4**（五段全管线装配）；后者交付的是**静态图像的结构化 prompt**（生图前的提示词设计）。用户只要「一张图的提示词」→ 转 gpt-image-prompting；要「能播放的文件」留在本 skill。

## E (Execution) — 可执行步骤

1. **需求确认与合规预告知** — 完成标准: 主题/受众/目标平台/画幅/时长/语言六要素确定，且用户已知悉成片对外发布须添加 AIGC 内容标识（见 B 段红线）
2. **凭据一次性盘点** — 完成标准: 缺失的 LLM key、素材源 key 等必需项合并为一次请求索取；对话全程绝不回显任何密钥或含密钥的配置片段
3. **脚本定稿** — 完成标准: 自定义脚本经校验直通或 LLM 生成稿获用户认可，同时产出逐句素材搜索关键词
4. **素材获取** — 完成标准: 每个关键词至少命中 1 条许可素材；图库无匹配时按「本地 → 文生视频」顺序降级并说明成本差异
5. **配音与字幕对齐** — 完成标准: TTS Provider 与音色确认（默认免费档 Edge TTS）；字幕时间轴逐句对齐，edge/whisper 二选一且取舍理由已说明
6. **合成与交付** — 完成标准: 返回实际存在且非空的 MP4 绝对路径，画幅与时长符合约定；附 AIGC 标识提醒与所用背景音乐的版权状态说明
7. **可选自动发布** — 完成标准: 仅当用户已配置 Upload-Post 并明确目标平台与可见性后才执行上传；否则止步于文件交付

## B (Boundary) — 边界

### 不适用场景
- 只要「一张封面图/海报的提示词」而非视频 → `gpt-image-prompting`
- 真人实拍素材的专业剪辑调色包装（非线性编辑软件的工作流）
- 强分镜导演逻辑的动画短片/广告片（本管线是素材装配逻辑，不是导演逻辑）
- 直播推流等实时流媒体场景（本管线只产出离线成片文件）

### 已知局限 / 失败模式
- 图库素材靠语义检索匹配，抽象/本土化主题易错配；whisper 字幕首次需下载约 3GB（large-v3）或 1.6GB（turbo）模型
- 上游自带背景音乐来自 YouTube 视频（README 自述「如有侵权请删除」），商用前必须替换为自有授权音乐
- CLI 参数优先级为 显式参数 > WebUI 保存值 > 内置默认值；自备音频路径不会被保存，每次命令行都必须显式传入 `--custom-audio-file`

### 合规红线（必须执行）
- **AIGC 内容标识义务**：依据《人工智能生成合成内容标识办法》，AI 生成的音视频对外发布必须添加显式标识（平台自主声明入口 + 元数据隐式标识）；交付成片时主动提醒；拒绝「去掉 AI 痕迹以便伪装真人原创」类请求
- **素材/音乐版权核查**：仅使用 Pexels/Pixabay/Coverr 等明确许可的素材及其允许的用途；影视解说/搬运涉及信息网络传播权，未获授权不得协助
- **平台规则**：不为「铺量养号」需求批量灌产同质化内容（触发限流与原创判定风险）；发布前建议人工过审内容质量
