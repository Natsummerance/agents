# GPT Image 2 结构化提示词引擎

## R (Reading) — 源项目核心设计

> "把『散文式提示词』压缩成『结构化协议』……当你需要批量出图、做模板系统、接进生产流程时，这种整理方式比单纯堆案例更有价值。"
>
> — 上游 README.zh-CN.md 项目愿景（freestylefly/awesome-gpt-image-2）

上游方法论：从 532 个真实案例逆向出 21 套工业级模板（自述「直接复制填空，再也不用玄学抽卡」），每套自带避坑指南；配套 style-library 以模板 ID、类别、风格/场景标签与示例案例号构成结构化索引，供 Agent 检索而非凭记忆填空。

## I (Interpretation) — 方法论骨架

1. **Prompt 即协议，读者决定格式**：给人看的一次性需求用文本填空模板；给 Agent/批量管线的需求用 JSON 进阶模板（字段即原子 schema：platform/layout/style/content/constraints）。原子化的意义在于让主体、光影、材质、版式成为可组合部件。
2. **四级匹配序**：产品类型锁类别（UI 73 例 / 海报排版 86 例 / 摄影写实 77 例 / 插画艺术 58 例 / 图表信息图 52 例等共 13 类）→ 视觉词锁风格标签 → 场景词锁场景标签 → 就近参考示例案例；请求模糊时不擅断，给 2-3 个候选方向让用户选后再动笔。
3. **六段构造块缺一不可**：主体与任务 / 构图与版式 / 风格与材质 / 文字与标签要求 / 比例与输出格式 / 约束与负面细节——每缺一段就留一分随机性，随机性即翻车率。
4. **防坑五锁**：① 平台特征显式指定（X 蓝勾、抖音音乐碟片、小红书双列瀑布流，不指定则模型混搭）；② 特殊比例写在指令最前（21:9 不写默认手机 9:16）；③ 文字逐字锁定（「必须准确显示指定的中文，禁止乱码和占位文本」）；④ 模块数量上限（信息图强制 3-5 模块防信息溢出）；⑤ 文案克制（短句入画，不塞大段正文）。

## A1 (Past Application) — 源项目典型应用

### 案例: Agent 批量 UI 截图
- **输入**: iOS 健身 App 深色模式界面图，卡内数据文字必须准确
- **做法**: 选 ui-screenshot-system 模板 → JSON 进阶格式逐字段填充（platform/product/layout/style/content）→ constraints 收尾 "High fidelity, readable text, 9:16"
- **结果**: 结构即契约，批量调用时每张图版式一致、文字可读，无抽卡

### 案例: 科学尺度缩放信息图
- **输入**: 需要从微观到宏观展示的科普主题
- **做法**: 尺度缩放模板限定「6-8 个尺度框递进排列 + 每框 3-5 词洞察 + 测量单位/放大倍率」，负面清单禁用通用放大镜图标、禁全同尺寸框、禁长正文入画
- **结果**: 层级清晰的知识卡片式科学信息图，无信息溢出

### 案例: 运动 Campaign 海报
- **输入**: 健身品类的社媒传播视觉
- **做法**: 海报模板锁定主体姿态 + 道具视觉锚点（夸张比例/对角构图）+ 大字标题层级 + 品牌化配色，约束排除杂乱拼贴与错误器材
- **结果**: 强主视觉的单张成品海报，可直接投社媒

## A2 (Future Trigger) ★ 触发场景

### 用户会在什么情境下需要
1. 要为 GPT Image 2 写高要求 prompt：界面截图/海报/信息图/产品图，尤其是图中文字必须准确显示的场景
2. 上一轮出图翻车（中文乱码/排版混乱/比例不对/平台特征错），需要诊断病因并收紧 prompt
3. 要给自动化流水线一套可参数化、可复用的生图 prompt 模板体系（JSON 版本）

### 语言信号

- "帮我写个 prompt 让 GPT Image 出一张……"
- "出来的图里中文全是乱码，prompt 怎么改"
- "我要一套能给程序反复调用的生图模板"
- "照着小红书/X 截图的样子生成一张"

### 与相邻 skill 的区分

- 与 `ai-short-video` 的区别: 本 skill 交付**静态图像的结构化 prompt**（止步于提示词本身，不执行生图后处理）；后者交付**动态成片 MP4**（脚本→配音→字幕→合成的全管线）。用户要「能播放的文件」→ 转 ai-short-video。

## E (Execution) — 可执行步骤

1. **归类细化** — 完成标准: 在 13 类别中锁定唯一类别；模糊主题已细化为具体命题（「健康」→「老年人日常健康管理指南」），目标平台与用途明确
2. **四级检索定方向** — 完成标准: 按类别→风格标签→场景标签→示例案例定位 ≥1 个参考案例；多解时给出 2-3 个方向由用户选择
3. **模板实例化** — 完成标准: 六段构造块全部填充；单次需求出文本版，管线需求另附 JSON 版；画幅比例位于指令最前
4. **防坑自查** — 完成标准: 平台特征、文字逐字锁定、模块数量上限、负面约束清单四项全部写入，并对照该类别避坑指南逐条过检
5. **语言跟随交付** — 完成标准: 中文请求出中文 prompt、英文请求出英文 prompt（除非用户另行指定）；先给可直接复制的完整 prompt
6. **实测迭代** — 完成标准: 实测仍乱码/错版时回到第 3 步收紧约束（逐字声明+数量上限+短句文案），不建议换模型逃避

## B (Boundary) — 边界

### 不适用场景
- 要的是带配音字幕的成品视频 → `ai-short-video`
- 已有图片的后处理（去水印/超分/抠图修复）
- 把 prompt 转成可用的 Figma 组件/前端代码（下游设计实现工作流）

### 已知局限 / 失败模式
- 模板自 GPT Image 2 行为逆向归纳，迁移到 Midjourney/FLUX 等模型时约束语法可能失效，需重写并重新校验而非宣称通用
- 中文长文案渲染随模型版本波动，prompt 只能降低乱码概率不能保证零错误，复杂文案建议拆分或后期替换
- 高仿截图类输出存在滥用敞口，正当用途存疑时先询问再产出（对应下方红线）

### 合规红线（必须执行）
- **伪造滥用防线**：截图/直播界面模板具备高仿能力，不得用于伪造他人账号发言实施诈骗、虚假传播或刷量举证；涉及真人姓名的截图请求须核实正当用途
- **权利核查**：名人肖像、品牌 LOGO、影视 IP 元素的商用生成需相应授权，请求存疑时主动提示风险并等待确认
