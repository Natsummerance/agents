# GPT Image 2 工业级提示词引擎

## R (Reading) — 源项目核心设计

> "After GPT-Image2 became widely available, AI image generation moved from 'can it make an image?' to 'can it make stable, controllable, reusable images?' ... compress prose-style prompts into structured protocols — this structure is more valuable than a pile of isolated examples."
>
> — 上游 README.md Project Vision（freestylefly/awesome-gpt-image-2）

上游方法论：从 532 个真实案例逆向出 21 套工业级模板，"直接复制填空，再也不用玄学抽卡"。原子化 schema 把主体、光线、材质、版式、视觉细节拆成可组合部件；每套模板自带避坑指南。

## I (Interpretation) — 方法论骨架

1. **结构优先于灵感**：先从 13 个类别（UI 73 / 海报排版 86 / 摄影写实 77 / 插画艺术 58 / 图表信息图 52 / 产品电商 41 / 角色人物 29 / 品牌标志 27 / 场景叙事 20 / 古风历史 16 / 建筑空间 12 / 文献出版 10 / 其他 28 例）中锁定类别，再进对应模板填空——拒绝无类别的自由发挥。
2. **双格式输出**：常规模板=文本填空段；JSON 进阶模板供 Agent/批量管线调用（字段即原子 schema）。人工单张用前者，自动化用后者。
3. **五大约束锁**（防坑核心）：① 平台特征显式指定（X 蓝勾 / 小红书双列瀑布流 / 抖音音乐碟片，不指定则模型混搭）；② 画幅比例写在指令最前（特殊屏幕如 21:9 不写就默认手机 9:16）；③ 文字逐字锁定（"必须准确显示指定的中文，禁止乱码和占位文本"）；④ 模块数量上限（信息图强制 3-5 模块防溢出）；⑤ 负面约束清单（不要 moodboard、不要拼贴、不要通用字效）。
4. **案例→模板两级检索**：先翻画廊找视觉基调（case album 定方向），再取模板定结构（template 定骨架），两者不可颠倒。

## A1 (Past Application) — 源项目典型应用

### 案例: 高保真社交截图
- **输入**: "生成一张小红书笔记截图，内容是护肤测评"
- **做法**: 套截图生成模板：平台特征 + 双列瀑布流 + 正文中文逐字给出 + 互动数据占位 + "禁止乱码"约束收尾
- **结果**: 文字清晰可读、平台特征正确的高仿截图，一次出图免抽卡

### 案例: 科普信息图
- **输入**: "老年人日常健康管理指南"信息图
- **做法**: 信息图模板限定"目标读者细化人群 + 5 模块上限 + 流程图表类型 + 短句文案"，拒绝大段正文入画
- **结果**: 信息层级清晰的中文信息图，模块不溢出不混乱

### 案例: 产品电商主图
- **输入**: 一款保温杯的详情页视觉需求
- **做法**: 产品电商模板填空：卖点逐条列出 + 包装/材质描述 + 详情页结构约束 + 负面清单排除杂乱拼贴
- **结果**: 卖点信息层级分明的商品视觉，可直接用于投放测试

## A2 (Future Trigger) ★ 触发场景

### 用户会在什么情境下需要
1. 要为 GPT Image 2 写一条高要求 prompt：界面截图 / 海报 / 信息图 / 产品图，且图中文字必须准确
2. 上一轮生成结果翻车（中文乱码 / 排版混乱 / 比例不对），需要诊断并修 prompt
3. 要给 Agent 或批量流水线一套可复用、可参数化的生图 prompt 模板体系

### 语言信号

- "帮我写个 prompt 让 GPT Image 生成……"
- "出来的图里中文全是乱码 / 排版乱了，怎么改"
- "我要一套能反复套用的生图模板"
- "按 XX 平台截图的样子生成一张"
- "给这个产品出一组电商图，卖点要体现在画面里"

### 与相邻 skill 的区分

- 与 `ai-short-video` 的区别: 本 skill 只产出**静态图像的结构化提示词**（prompt 工程，交付物是 prompt 本身）；后者是**动态成片全管线**（脚本→配音→字幕→MP4）。用户要的是"一段稳定出图的提示词"留在这里；要"能发布的视频文件"→ 转 ai-short-video。

## E (Execution) — 可执行步骤

1. **需求归类** — 完成标准: 在 13 类别中选定唯一类别 + 明确目标平台与用途，模糊主题（如"健康"）已细化为具体命题
2. **方向检索** — 完成标准: 在画廊中定位 ≥1 个参考案例，确定视觉基调与风格关键词后再动笔
3. **模板实例化** — 完成标准: 按该类别常规模板完成填空，主体/风格/构图/光线/色调五要素齐备，画幅比例位于指令最前；批量场景另产出 JSON 版本
4. **锁定与防坑自查** — 完成标准: 文字逐字锁定声明、模块/元素数量上限、负面约束清单三项全部写入，并对照该类别避坑指南逐条过检
5. **迭代交付** — 完成标准: 输出最终 prompt；若实测仍乱码/错版，回到第 3 步收紧约束而非建议换模型

## B (Boundary) — 边界

### 不适用场景
- 要的是带配音字幕的成品视频 → `ai-short-video`
- 已有图片的后处理（去水印/超分/抠图修复）
- 把 prompt 转成可用的 Figma 组件/前端代码（设计实现工作流）

### 已知局限 / 失败模式
- 模板自 GPT Image 2 行为逆向归纳，迁移到 Midjourney/FLUX 等模型时约束语法可能失效，需重写校验而非照搬
- 中文长文案渲染仍随模型版本波动，prompt 只能降低乱码概率不能保证零错误——复杂文案建议拆分或后期替换
- 高仿截图类输出存在被滥用的风险敞口，正当用途存疑时应先询问再产出（对应 B 段红线）

### 合规红线（必须执行）
- 截图/直播界面模板具备高仿能力，**不得用于伪造他人账号截图实施诈骗、虚假传播或刷量举证**；涉及真人姓名的截图请求须核实正当用途
- 名人肖像、品牌 LOGO、影视 IP 元素的商用生成需相应授权，请求存疑时主动提示风险
